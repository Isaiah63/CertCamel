1. Private keys on disk

This is the largest exposure here, and it is unavoidable

certs\ and acme-state\ contain unencrypted private keys. That is how PEM works, and every ACME client on every platform is the same. Nothing in this tool can change it — a load balancer has to be handed a key it can actually use.

Both folders are excluded from git. Gitignore does not stop file sync. If this folder lives inside OneDrive, Dropbox, Google Drive or similar, exclude those two folders — otherwise your private keys are being copied to somebody else's servers.

Worth separating from the other thing people mean by “keys”: your API credentials — DNS tokens, load balancer and SMTP passwords — live in a different store and are encrypted. See Credentials.

Download on a certificate saves the certificate, its chain and its private key as one PEM into your Downloads folder, in the clear. That is the point of the button, and it is also a second copy of the key in a folder nothing is watching. Delete it once deployed.

2. What loopback, the token and the Host check actually do

The page is served from 127.0.0.1, and every API request needs a token minted fresh each time the server starts.

Loopback is not access control. Every other program running on this PC can reach 127.0.0.1, and so can any web page you happen to have open in a browser. That is precisely why the token exists — not to keep out the network, which cannot reach it anyway, but to keep out other software on the same machine.

Three consequences follow, and they are worth knowing because they decide what a URL can and cannot do:

  • The token does not stay in the address. It arrives on the query string, because that is the only way the server can hand it to a page it is opening, and the page stores it for the tab and rewrites the address immediately. Nothing live is left in history, in a browser profile syncing to an account, or in a screenshot. Started at boot, the server serves one token for as long as the machine stays up — so an address copied out of history weeks later would otherwise still work.
  • No address produces a private key. The download is a request the page makes with the token in a header; opening the same address directly is refused. It is the only secret the API hands back at all — every stored credential comes back as a yes/no that one exists, never as itself.
  • Requests must carry a Host header this server recognises — 127.0.0.1, localhost, or the tracker hostname you configured. A hostile page can point a name it owns at 127.0.0.1, but it cannot forge the header the browser sends. The check runs in front of the pages and their data, not only the API, because that kind of attack goes for whatever needs no token — and ssl-data.js is your whole estate: every hostname, issuer, expiry and serial.
It is not designed to be exposed to a network

There is no login, no user accounts and no roles. The token is the only thing between a caller and everything the tool can do.

The web server is also single-threaded, with a fifteen-second receive timeout: one client that connects and sends nothing blocks it for that long. Fine on loopback, and not fine on a network anyone else can reach, where a vulnerability scanner alone would stall it repeatedly.

3. Credentials

DNS API tokens, load balancer passwords and any SMTP password are encrypted with Windows DPAPI and stored in secrets.xml. They are never written to settings.json, and never sent to the browser — the page is told only whether a credential exists.

A blank credential field means “keep what is stored”, so an unchanged form cannot wipe a credential nobody retyped.

DPAPI protects the file, not the session. Copy secrets.xml to another machine and it is useless, but anything already running as you on this one can decrypt it. That is the normal bar for a local tool; it is not a vault.

Credentials are bound to one Windows account on one machine

A feature — copy the folder to a colleague and nobody inherits your API keys — and a trap. Change which account runs Cert Camel and it can no longer decrypt its own credentials: DNS automation and deployments start failing while everything else looks fine. Re-enter them as the new account.

The same applies to backups. certs\ and acme-state\ restore to new hardware; credentials do not.

4. What is recorded, and what never is

audit.log records one line per state change — when, who, whether a person or the scheduler did it, what changed, and whether it worked. It is append-only and deliberately exempt from log retention, because deleting audit records to reclaim disk is the opposite of the point. Credential changes are recorded too, by key name only.

What never reaches either log

No credential value, no private key, no certificate body. Every line goes through a redaction pass on the way in, so a debug line added later cannot leak one by accident.

5. What needs administrator, and why

TaskAdmin?Why
Watching certificatesNoNothing is installed
Renewing and deployingNoPosh-ACME is fetched into the folder, not the system
Tasks that run while you are signed outYesNeeds the Log on as a batch job right
Starting the page at boot on a serverYesSame
Serving under a hostnameYesOnly to write the hosts file entry

If setup is run without elevation it still works, but the scheduled tasks fall back to running only while you are signed in — and it says so at the time. On a server that is silently fatal: the renewal never fires, Task Scheduler still reports the task as healthy, and the first symptom is an expired certificate.

6. What it does not do

  • No telemetry, no analytics, no phoning home.
  • No CDN and no external fetch of any kind — the page loads nothing from the internet, so it works on an isolated network. That includes these guides: they ship in the folder and are served from it, which is why they are readable exactly when a DNS or TLS problem has broken everything else.
  • No build step and no package manager. What you download is what runs.
  • Nothing that belongs to you is committed to git — domains, credentials, certificates and logs are all excluded, so the folder can be handed on clean.

7. Reporting something

There is no public issue tracker yet. If you find a security problem, get in touch through wherever you obtained this, and please do that rather than posting it somewhere public.

This is a one-person beta project. There is no security team and no response-time promise, which is itself worth weighing before you deploy it somewhere that matters.
